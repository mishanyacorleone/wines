# Матчинг каталога (CSV ↔ rar-архив)

Задача: связать текстовую запись о вине (`strapi_output0709.csv`) с конкретным файлом фото в rar-архиве, чтобы получить пары `(изображение, slug)` для построения индекса.

Это заняло несколько итераций из-за неочевидных свойств данных. Ниже — итоговая рабочая логика и все найденные подводные камни, чтобы не наступать на те же грабли повторно.

## Итоговый результат

**1652 из 2090 уникальных `Название фото` (79%) успешно сматчены** с реальным файлом в архиве.

## Правильная логика матчинга

### Шаг 1: ключ — `Название фото`, НЕ `Slug`

Первая гипотеза (матчить по `Slug`) была неверной. `Slug` мог измениться после того, как фото уже загрузили (переименование товара в Strapi), поэтому у части строк `Slug` и имя файла на диске расходятся.

Пример:
- `Slug`: `fanagoriya-100-ottenkov-krasnogo-pino-nuar-krasnoe-suhoe-135`
- `Название фото`: `fanagoriya-100-ottenkov-krasnogo-pino-nuar-krasnoe-suhoe-vyderzhannoe-135.webp`

Файл на диске построен именно от `Название фото`, а не от текущего `Slug`.

### Шаг 2: нормализация имени + отрезание хэш-суффикса

Strapi при загрузке медиа генерирует имя файла на диске так: берёт исходное имя (`Название фото`), заменяет `-`/пробелы на `_`, добавляет случайный hex-суффикс.

Пример:
- CSV: `zolotoe-pole-kaffa-malbek-krasnoe-suhoe-125.webp`
- Архив: `zolotoe_pole_kaffa_malbek_krasnoe_suhoe_125_59cab68c16.webp`

Код нормализации:
```python
def name_to_prefix(name: str) -> str:
    base = os.path.splitext(name)[0]
    return re.sub(r"[\s-]+", "_", base.strip())
```

И обратное — извлечение префикса из реального файла (отрезание хэш-суффикса):
```python
def strip_hash_suffix(fname: str) -> str:
    m = re.match(r"^(.*)_[0-9a-f]{6,}(\.[A-Za-z0-9]+)$", fname)
    return m.group(1) if m else os.path.splitext(fname)[0]
```

Строится индекс `{нормализованный_префикс: [реальные_файлы]}`, и для каждого `Название фото` из CSV ищется совпадение.

### Шаг 3: отфильтровать авто-превью Strapi

Файлы `thumbnail_*`, `small_*`, `medium_*`, `large_*` — производные превью, не основной файл. Исключаются из индекса до матчинга (иначе один slug матчится на несколько файлов сразу).

## Честная классификация несопоставленных 21% (438 записей)

Первая версия классификации ("похоже на slug — не похоже") была слишком грубой: строка `fpZEJhYZPstBYLV_1775199670` формально проходит как "буквы+цифры+дефисы", но на деле это случайный ID аплоадера + unix-timestamp, а не осмысленный slug. Финальная версия делит на 5 категорий по реальной структуре:

| Категория | Что это | Кол-во (пример) | Можно доразобрать автоматически? |
|---|---|---|---|
| `cyrillic_original` | Оригинальные имена с кириллицей (`Москато Розовый.webp`) | 343 | Возможно — стоит проверить отдельно, файл может физически лежать в архиве |
| `slug_like_but_unmatched` | Похоже на осмысленный slug (словообразные токены с гласными), но файл не нашёлся (`Cantiani-CaberSauv_vid_042024-Photoroom.webp`, `IMG-20250829-WA0033.webp`) | 31 | Только руками, по одному — реальные кандидаты |
| `other` | Не попало ни в одну категорию | 28 | Руками |
| `base64_hash` | Длинная base64-подобная строка, S3/CDN-хэш | 20 | Нет — скорее всего фото просто отсутствует в архиве под этим именем |
| `uploader_hash_id` | nanoid-подобный ID + unix-timestamp (мобильный аплоад), напр. `fpZEJhYZPstBYLV_1775199670` | 10 | Нет |
| `camera_photo` | Имя файла с камеры (`DSC09173.webp`) | 6 | Нет напрямую — но такое фото может быть переиспользовано на несколько slug (см. ниже) |

Код классификации:
```python
def classify_unmatched(name: str) -> str:
    base = os.path.splitext(name)[0]
    if re.search(r"[а-яА-ЯёЁ]", base):
        return "cyrillic_original"
    if re.fullmatch(r"(DSC|IMG|Photo)[_\-]?\d+", base, re.IGNORECASE):
        return "camera_photo"
    if re.fullmatch(r"[A-Za-z0-9]{10,25}_\d{10}", base):
        return "uploader_hash_id"
    if len(base) > 40 and re.fullmatch(r"[A-Za-z0-9+/=_\-]+", base):
        return "base64_hash"
    tokens = re.split(r"[-_]", base)
    word_like = [t for t in tokens if len(t) >= 2 and re.search(r"[aeiouAEIOU]", t)]
    if len(tokens) >= 2 and len(word_like) >= len(tokens) * 0.5:
        return "slug_like_but_unmatched"
    return "other"
```

## Побочная находка: одно фото на несколько `Slug`

13 файлов используются сразу для >1 разного `Slug` (обычно — одно вино разных урожаев без отдельной пересъёмки):

```
DSC09173.webp -> {aligote-barrel-2024, aligote-barrel-2025}
Агора Резерв Яхтинг Совиньон — копия.webp -> {agora-yachting-sauvignon, agora-yachting-cabernet-sauvignon}
bottle-02-Cabernet_Franc.webp -> {cabernet-franc-pinot-noir-2021, cabernet-franc-pinot-noir-2022}
...
```

Важно для построения индекса: "1 фото → 1 однозначный slug" не всегда верно. Учитывать при построении эмбеддингов (не дублировать слепо, либо явно решить, как обрабатывать такие случаи).

## Что дальше с оставшимися 21%

Основной путь закрытия пробела — не ручной разбор всех 438 записей, а **парсинг сайта vino-svoe.ru напрямую** (см. `scraper.md`), который даёт официальный, актуальный slug + фото без зависимости от того, как Strapi исторически назвал файл при аплоаде. Ручной разбор имеет смысл точечно, для категории `slug_like_but_unmatched` (31 запись) — она наиболее вероятно содержит реальные "почти-совпадения", которые парсинг сайта не обязательно закроет автоматически (нужно сверить).
