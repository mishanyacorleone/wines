## 27.09.2026 — VLM в сервисе, Excel с результатами, подготовка к GitHub

### VLM-реранкер встроен в сервис (`services/search-api`)

- **`config.py`** — `WINE_VLM_ENABLED` (**по умолчанию `0`**), `WINE_VLM_MODEL_DIR`,
  `WINE_VLM_TOP_K`, `WINE_VLM_CANDIDATE_IMAGES`, `WINE_VLM_QUERY_MAX_PIXELS`,
  `WINE_VLM_CANDIDATE_MAX_PIXELS`, `WINE_CATALOG_DIR`. Значения по умолчанию —
  лучший офлайн-вариант: текст + эталонные фото, картинки 512k / 128k px.
- **`search.py`** — после картинки и OCR VLM выбирает внутри первых 5 и
  пересортировывает их; `confidence` = вероятность VLM. Кандидатов из Qdrant
  берётся не меньше 5, даже для `/v1/eval/predict` (там нужен один ответ).
- **`schemas.py`** — у кандидата `vlm_prob`, в ответе `vlm_none_prob`, в таймингах
  `vlm_ms`, в `/health` `vlm_enabled`. `margin` с VLM считается по `confidence`.
  Контракт `/v1/eval/predict` не изменился.
- **`main.py`** — VLM поднимается на старте; без весов сервис падает с понятной
  ошибкой. **Прогрев**: холостой поиск по белой картинке на старте — без него
  первый запрос занимал 3,4 с (холодные CUDA-ядра SigLIP и первый запрос к Qdrant),
  с ним — 1,3 с. Касается и конфигурации без VLM.
- Проверка через HTTP на 100 фото (VLM вкл., OCR выкл.): top-1 **96,2%** / 93,9%,
  выдача совпала с офлайн-прогоном, p95 = 1682 мс, max 2303 мс, 0 ошибок.
  Прогон — `data/reports/service-vlm/`. Конфигурация по умолчанию (OCR, без VLM)
  перепроверена: 88,7%, как было.

## 23–24.09.2026 — OCR-переранжирование и ручная разметка

### Итог

|---|---|---|---|---|

### OCR-переранжирование (`services/search-api`)

- **Новое `search_api/ocr.py`** — `LabelReader`: EasyOCR (`ru`+`en`), фото
  уменьшается до 1280 по длинной стороне, строки с уверенностью < 0,3 отброшены.
  Веса только с диска (`download_enabled=False`).
- **Новое `search_api/text_match.py`** — `TextMatcher`: какие слова карточки
  (`title`, `manufacturer`, `category`, `grapes`) нашлись на этикетке.
  Нечёткое сравнение в транслите, склейка разорванных слов, латинские двойники
  кириллицы, синонимы brut/extra/rose, одно слово в двух алфавитах — одна улика,
  вес слова — IDF по каталогу, штраф за противоречие по цвету/сладости.
  `text_score = min(Σ IDF / 40, 1) − 0,15 × конфликты`.
- **`search.py`** — картинка отдаёт топ-20, текст переставляет:
  `score = cos + 0,15 · text_score`. Softmax теперь по итоговому баллу.
- **`main.py`** — OCR и словарь IDF (по payload из Qdrant) поднимаются на старте;
  `/health` показывает `ocr_enabled`.
- **`schemas.py`** — у кандидата новые поля `image_score`, `text_score`,
  `matched_terms`, `conflict_terms`; в ответе `ocr_text`, в таймингах `ocr_ms`.
  Контракт `/v1/eval/predict` не изменился.
- **`config.py`** — `WINE_OCR_ENABLED`, `WINE_OCR_MODELS_DIR`, `WINE_OCR_MAX_SIDE`,
  `WINE_OCR_MIN_CONFIDENCE`, `WINE_RERANK_K`, `WINE_TEXT_WEIGHT`.
- **`requirements.txt`** — `easyocr==1.7.2`, `rapidfuzz==3.14.6`,
  `torchvision==0.23.0` (пин обязателен, см. ниже).

### Инфраструктура

- **Новое `infra/fetch-ocr.sh`** — веса EasyOCR (94 МБ) в `models/easyocr`,
  curl с докачкой и проверкой md5.
- **Инцидент с окружением.** `pip install easyocr` поднял torch 2.8 → 2.14
  (CUDA 13). Откатено на `torch==2.8.0` + `torchvision==0.23.0` + `nvidia-*-cu12`
  (`--force-reinstall --no-deps`: удаление пакетов cu13 стирает общие `.so`).
  GPU проверен. Рецепт — в CLAUDE.md.

### Оценка качества (`tools/eval-runner`)

- **Новое `eval_runner/labels.py`** — импорт экспорта Label Studio (CSV) в
  `data/labels/real-photos.json`: срезает префикс `/data/upload/<id>/<hash>-`,
  отделяет комментарий после `__`, сверяет slug с каталогом.
- **Новое `eval_runner/score.py`** — top-1 / top-5 / recall@20 / MRR по
  разметке для любого `results.jsonl`, отдельно «уверенные» и «+ не уверен»;
  разделимость «нет в каталоге» по баллу топ-1.
- **`runner.py`, `report.py`** — в отчёте текст OCR, время OCR, разбивка балла
  (картинка / текст) и найденные/противоречащие слова у каждого кандидата.
